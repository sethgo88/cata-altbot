-- A. The actual rows the loader sees, in load order                     
  SELECT gm.guildid, gm.guid, gm.`rank`, c.name, c.level, c.class, c.zone, 
         c.account, c.logout_time, c.achievementPoints                     
  FROM guild_member gm                                                     
  LEFT JOIN characters c ON c.guid = gm.guid                               
  WHERE gm.guildid = 1                                                     
  ORDER BY gm.guildid;                                                     
                                                                           
  -- B. Rank validity (rank id must exist in guild_rank for that guild)    
  SELECT gm.guildid, gm.guid, gm.`rank`                                    
  FROM guild_member gm                                                     
  LEFT JOIN guild_rank gr                                                  
    ON gr.guildid = gm.guildid AND gr.rid = gm.`rank`
  WHERE gr.rid IS NULL;                                                    
                                                                     
  -- C. Withdraw / reputation join sanity (LEFT JOINs, NULLs are OK but    
  worth seeing)                                                      
  SELECT gm.guid,                                                          
         (SELECT COUNT(*) FROM guild_member_withdraw w WHERE w.guid =
  gm.guid) AS has_withdraw,                                                
         (SELECT COUNT(*) FROM character_reputation r WHERE r.guid =
  gm.guid AND r.faction = 1168) AS has_rep                                 
  FROM guild_member gm WHERE gm.guildid = 1;                         
                                                                           
  -- D. Skill rows for those bots — LoadProfessionDataFromDB iterates these
  SELECT cs.guid, cs.skill, cs.value, cs.max                               
  FROM character_skills cs                                                 
  JOIN guild_member gm ON gm.guid = cs.guid                          
  WHERE gm.guildid = 1;                                                    
                                                                     
  What I'm hunting for in those:                                           
  - A: level=0 or class=0/out-of-range → CheckStats would reject (not
  crash), but a NULL name or weird zone might be the trigger.              
  - B: gm.rank pointing at a rank that doesn't exist for that guild — TC
  doesn't validate, and the rank index is later used as an array offset    
  into m_ranks. This is the most likely crash shape for "guild has 5 ranks,
   member references a 6th."                                               
  - D: any skill row with max=0 would cause max / 75 in                    
  LoadProfessionDataFromDB to be 0 — not a crash, but worth seeing what's
  there.
