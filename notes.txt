To diagnose the startup crash at guild-member load, the most useful      
  artifacts are:                                                           
                                                                           
  1. Worldserver console output from launch through the crash — the line   
  right before the crash usually names the guild ID / member GUID it choked
   on. Capture stderr too.                                                 
  2. Server.log / Errors.log from server-core/build/.../logs/ (whatever
  your LogsDir is set to in worldserver.conf).                             
  3. Stack trace — if it's a real crash (segfault), there should be a .dmp
  next to the binary on Windows or a crash log in the logs dir on          
  macOS/Linux. On macOS, Console.app → "Crash Reports" usually has it; or
  run under lldb -- ./worldserver and paste bt after it dies.              
  4. What "can't build" means — is the compile failing, or is it the 
  worldserver process crashing at startup? If compile, paste the           
  cmake/ninja output. If startup, that's the same as #1.
  5. DB state sanity check — the queries SELECT COUNT(*) FROM guild_member;
   and SELECT guildid, COUNT(*) FROM guild_member GROUP BY guildid ORDER BY
   2 DESC LIMIT 5; against the characters DB. A bot that got added to a
  guild then had its character row deleted will leave a dangling           
  guild_member row pointing at a missing character — that's a known crash
  shape.

  If you paste the last ~50 lines of console output before the crash plus  
  any stack trace, that's usually enough to pinpoint it. Which would you
  like to grab first?
